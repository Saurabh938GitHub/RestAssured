- API: application programming interface which acts as a bridge between client(front end) and server (back end)

- End point: Address where API is hosted on the Server.

- HTTP methods which are commonly used to communicate with Rest API’s are: GET, POST, PUT, and DELETE (CRUD operations)

- GET http method: The GET method is used to extract information from the given server using a given URI. While using GET request, it should only extract     data and should have no other effect on the data. No Payload/Body required
How to send input data in GET?
Ans: Using Query Parameters

- POST http method: A POST request is used to send data to the server, for example, customer information, file upload, etc. using HTML forms.
How to send input data in POST?
Ans: Using Form Parameters /Body Payload

- PUT http method: Replaces all current representations of the target resource with the uploaded content.

- DELETE http method: Removes all current representations of the target resource given by a URI.


- End Point Request URL can be constructed as below: Base URL/resource/(Query/Path)Parameters

- Resources: Resources represent API/Collection which can be accessed from the Server like for google its maps/images/search

- Path Parameters: Path parameters are variable parts of a URL path. They are typically used to point to a specific resource within a collection, such as a user identified by ID
Example: https://amazon.com/orders/1123343 --  here 'https://amazon.com/' is server, 'orders' is resource and '1123343' is path parameter/specific order

- Query Parameters: Query Parameter is used to sort/filter the resources. Query Parameters are identified with '?'
Example: https://amazon.com/orders?sort_by=2/20/2020 --  here 'https://amazon.com/' is server, 'orders' is resource and 'sort_by=2/20/2020' is query parameter

- Headers/Cookies: Headers represent the meta-data associated with the API request and response. In layman terms, we were sending Additional details to API to process our request.
Example : Authorization details

Authentication
--------------------------------------------------------------------
- Basic auth(Simple Basic Auth using Username + password): given().auth().preemptive().basic("admin", "password").when().get("/secure-api").then().statusCode(200);
In Postman: Authorization Tab- Select Auth Type as Basic Auth - provide Username and Password

Authorization
--------------------------------------------------------------------
- Bearer Token(Token-based authentication): authentication using bearer-token in BASE64 encoding(often JWT). User needs to generate a bearer token for authenticating. It is done under header named Authorization.
given().header("Authorization", "Bearer " + token).when().get("/users").then().statusCode(200);
In Postman: Authorization Tab- Select Auth Type as Bearer Token - provide Token (OR) Headers Tab - Add Key: Authorization and Value: Bearer {{token}}

- API Key(light weight than Bearer Token): authentication using API key provided by the API provider / service owner like registering on the API provider’s portal
given().header("x-api-key", "abc123") or given().queryParam("api_key", "abc123")
In Postman: Authorization Tab- Select Auth Type as API Key - provide Key, Value, Add to (either Header or Query Params)

-- O-Auth2.0: internal server apis communication. here the internal apis secured with o-auth authorisation will need access token to get unlocked. that access token is provided by access/authorization server which first needs to verify whether relevant user/party is asking for access token or not. if not, it will deny, if yes, access token will be shared. this verification is done through grant type process. there are two grant type processes: client credential grant type and password grant type. Once access token is given using verification of these grant types, that access token can be user to hit and get response from apis secured with o-auth authorisation.
1. client credentials grant type: 
Postman: Authorization Tab- Select Auth Type as OAuth2.0 and provide Grant type as Client Credentials, Access Token URL (endpoint to get access token), Client Id, Client Secret, Scope and Client Authentication (as Send as Basic auth header) Rest Assured: .formParams("client_id", "").formParams("client_secret", "").formParams("grant_type","client_credentials")
.formParam("scope", "trust") and through this we can get access token which can be then used in another api request
2. password credentials grant type: 
Postman: Authorization Tab- Select Auth Type as OAuth2.0 and provide Grant type as Password Credentials, Access Token URL (endpoint to get access token), Client Id, Client Secret, Username, Password, Scope and Client Authentication (as Send as Basic auth header)
Rest Assured: .formParams("client_id", "").formParams("client_secret", "").formParams("grant_type","password").formParams("username","").formParams("password","")
.formParam("scope", "trust") and through this we can get access token which can be then used in another api request

.queryParam() — single parameter
Ex: given().queryParam("page", 1).queryParam("size", 10)

.queryParams() — multiple parameters at once
Ex: given().queryParams("page", 1, "size", 10)

-------------------------------------------------------------------

.header() — single header
Ex: given().header("Authorization", "Bearer token123")

.headers() — multiple headers
Ex: given().headers(
        "Authorization", "Bearer token123",
        "Content-Type", "application/json")
------------------------------------------------------------------

.pathParam() — single path parameter
Ex: given().pathParam("userId", 10)

.pathParams() — multiple path parameters
Ex: given().pathParams("userId", 10, "orderId", 99)
Or: Map<String, Object> params = new HashMap<>();
params.put("userId", 10);
params.put("orderId", 99);

given().pathParams(params)
-----------------------------------------------------------------

.formParam() — single form field
Ex: given().contentType(ContentType.URLENC).formParam("username", "admin")

.formParams() — multiple form fields
Ex: given().contentType(ContentType.URLENC).formParams(
        "username", "admin",
        "password", "secret")

-----------------------------------------------------------------
.multiPart() — single part
Ex: given().multiPart("file", new File("test.pdf"))

.multiParts() — multiple parts at once
Ex: given().multiParts(
        multiPart("file1", new File("a.pdf")),
        multiPart("file2", new File("b.pdf")),
        multiPart("category", "docs"))


Note:
1. param() → Generic parameter method; REST Assured decides whether it becomes a query or form parameter based on request context. Do not use if type is known.
2. queryParam() → Sends parameters explicitly in the URL query string (?key=value).
3. pathParam() → Replaces placeholders in the URL path (e.g., /users/{id}).
4. formParam() → Sends parameters in the request body as form data (application/x-www-form-urlencoded).

generic methods post .then()
------------------------------------------
1. .statusCode(200)- Asserts the HTTP status code.
2. .statusLine("HTTP/1.1 200 OK")- Asserts the complete HTTP status line.
3. .header("Content-Type", "application/json")- Asserts a single response header.
4. .headers("Content-Type", "application/json")- Asserts multiple response headers at once.
5. .contentType(ContentType.JSON)- Asserts the response Content-Type.
6. .body("id", equalTo(10))- Asserts values inside the response body.
7. .time(lessThan(2000L))- Asserts response time.
8. .log().all()- Logs request or response details.
9. .assertThat().statusCode(200)- Improves readability before assertions (syntactic sugar)
10. .extract().path("id")- Extracts data from the response for reuse.

Note: all status, status line, header(s), body, contentType, time validations can also be done post .assertThat() instead of .then() with exactly same method names and it just improve human redability

generic methods post .extract()
------------------------------------------
1. .statusCode()- Extracts the HTTP status code as an integer.
2. .statusLine()- Extracts the complete HTTP status line.
3. .header("Content-Type")- Extracts a single response header.
4.  Headers headers = response.then().extract().headers();- Extracts all response headers.
5. .contentType()- Extracts the response Content-Type.
6. .body().asString()- Extracts the full response body as a ResponseBody object
7. .time()- Extracts response time.
8. .path("id")- Extracts data from the response for reuse.
9. .jsonPath().getString("name")- Returns a JsonPath object for complex JSON extraction
10..xmlPath().getString("user.id")- Returns an XmlPath object for XML response parsing
11. .response()
